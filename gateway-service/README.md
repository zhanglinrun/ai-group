# `gateway-service`（API 网关）

这是 `ai-group`（平台层）的统一入口。所有前端请求都先到这里，由它校验登录、识别用户身份，再转发到后面的各个服务。它基于 `Spring Cloud Gateway`（响应式网关），跑在 `WebFlux`（响应式 Web 框架）上。

一句话概括它的职责：**在请求进入业务系统之前，先把「你是谁、能不能进」这件事定下来。**

---

## 它主要做四件事

### 1. 校验登录令牌

带 `JWT`（登录令牌）的请求进来，网关先验签、查有效期，再确认它确实是访问令牌（不是刷新令牌）。任何一步不过就直接挡回 `401`（未授权），根本不会到达下游服务。

### 2. 注入可信身份头，剥离伪造身份头

令牌校验通过后，网关把解析出的 `userId` / `username` / `role` 通过请求头传给下游，同时带上内部令牌，等于给下游签了个「这是我放行的」凭证。

反过来，对于不需要登录的白名单请求，网关会主动剥掉外部可能伪造的身份头，防止有人绕过登录直接伪造用户身份。下游服务只认「带正确内部令牌」的身份头，两头配合形成闭环。

### 3. 放行白名单和内部回调

有两类请求不走普通的 `JWT` 校验：

- **白名单**：登录、注册、刷新令牌、支付宝异步回调、健康检查等，不需要登录就能访问。
- **内部回调**：像拼团成团通知这种服务间回调，用共享的内部令牌校验，校验通过才放行并补上内部令牌转发给下游。

### 4. 处理跨域

`GlobalCorsConfig`（全局跨域配置）统一处理 `CORS`（跨域），让前端能正常调用。

---

## 端口与路由

- 服务端口：`8080`
- 路由和下游服务通过 `Nacos`（注册中心）发现，转发到 auth、member、bff、group、pay、agent 等服务。

核心代码：

- `AuthGlobalFilter`（全局鉴权过滤器）：上面四件事的主要逻辑都在这里。
- `GatewayIdentityHeaderSupport`（身份头处理支持）：注入可信身份、剥离伪造身份、补内部令牌。
- `GatewayConfig`（网关配置）、`GlobalCorsConfig`（跨域配置）。

---

## 本地运行

依赖 `Nacos`（注册中心）和 `Redis`（缓存，用于令牌黑名单）。通常不用单独起，跟着平台一套启动脚本走即可：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File docs/dev-ops/start-full-stack.ps1
```

只想单独跑，先确认 `Nacos`、`Redis` 已就绪，再执行：

```bash
cd gateway-service && mvn spring-boot:run
```

配置文件在 `src/main/resources/application.yml`（主配置）和 `application-local.yml`（本地配置）。

---

## 安全提醒

网关是整个平台的安全第一道关，改动时注意别破坏这几点：

- 白名单只放真正不需要登录的路径，别图省事把业务接口加进去。
- 身份头的「注入 + 剥离」是一对，少了剥离那一半，伪造身份头就能直连下游。
- 内部令牌是服务间互信的凭证，必须走配置和环境变量，不能硬编码，也不能用默认值上生产。
